# 東吳第3哩｜環島角色測驗 1010_BE_v3

來源：1010_v6（純前端穩定備份）。本版本只增加匿名資料背景送出；保留原 Q1～Q8、計分、最終角色判斷、視覺版面、結果 PNG 與保存流程。

## 啟用方法

1. `backend-config.js` 已填入 Apps Script Web App 的 `/exec` 網址，不需要自行修改。若日後重新部署並更換網址，再修改這個檔案。
2. `backend.js` 已將資料版本設成 `1010_BE_v3`。上傳測試網站前，請先在 Apps Script 的 `allowedVersions` 加入 `"1010_BE_v3"`，並更新原有 Web App 部署為新版本。
3. 在本機／獨立測試站測試。**未填網址時，網站照常運作但完全不傳送。**
4. 確認測試後，再將壓縮檔內的檔案與 `assets` 資料夾上傳到 GitHub Pages 儲存庫根目錄（不是上傳 ZIP 本身）。

## 背景傳送規則

- 按「開始測驗」或「再測一次」建立新的隨機 UUID，完成 Q8 產生結果時發送一次。
- 切換結果圖片與返回不會再次提交。重新開始並完成測驗才計新的一次。
- 使用 `fetch(..., mode: "no-cors", keepalive: true)`、`text/plain`，不等待後端、沒有自動重試。瀏覽器無法讀取此模式的真正儲存成功訊息，必須在 Google Sheets 確認。
- 計分與顯示先完成，傳送失敗不影響結果及圖片功能；前端是否能正常載入仍依賴 GitHub Pages 及使用者網路。
- 若瀏覽器無 `crypto.randomUUID()`（例如某些非安全本機網址），該次不傳送，但測驗照常顯示。GitHub Pages HTTPS 正常支援。
- 所有公開前端碼與接收網址都可被看到；此設計不防惡意灌入假提交。不可放任何密碼／私密金鑰。

## 驗收與回退

1. 先在測試站打開網頁，完成 Q1～Q8，檢查 Sheets 多一筆、四種百分比正確、Q8 其他文字（若填）正確。
2. 再測一次應新增新的提交 ID；在結果與圖片頁來回切換不應新增。
3. 將 `backend-config.js` 的網址暫時清空，再完整測驗、保存結果 PNG，應全部正常，且不新增紀錄。
4. 先保留 `1010_v6.zip` 與正式網站的 Git commit。若 v1 異常，可重新發布 v6 的檔案或回復對應 commit。後端既有資料不會因此消失。

## 避免修改正式 GitHub Pages

可建立另外一個**私人開發目錄**本機測試，或另外一個公開 GitHub Repository 作為測試站（GitHub Pages 若對外可見，請勿放私人資料）。新 Repository 並非必要，也不會自動取代原本的正式網址。
